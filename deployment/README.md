# Backend deployment

This directory contains the CP-019 deployment boundary for the CarePath backend.

## Local Docker Compose

Prerequisites: Docker Engine with Docker Compose v2.

```bash
cp deployment/.env.compose.example deployment/.env.compose
# Replace CAREPATH_POSTGRES_PASSWORD with a local-only password.
docker compose --env-file deployment/.env.compose up --build --wait
```

The stack contains:

- `api`: the FastAPI backend built from the repository `Dockerfile`;
- `db`: PostgreSQL 16 with a named data volume;
- `evidence_index`: a named volume mounted at `/app/data/guidelines/qdrant` for the existing Qdrant Local index architecture.

The API container waits for PostgreSQL to become healthy, runs `alembic upgrade head`, and then starts Uvicorn. No database port is published to the host. The API is exposed on `CAREPATH_API_PORT`, default `8000`.

Verify the stack:

```bash
curl --fail http://127.0.0.1:8000/health/live
curl --fail http://127.0.0.1:8000/health/ready
curl --fail http://127.0.0.1:8000/openapi.json >/dev/null
```

Stop and remove containers:

```bash
docker compose --env-file deployment/.env.compose down
```

Add `-v` only when you intentionally want to delete the PostgreSQL and evidence-index volumes.

## Health checks

Three endpoints exist for distinct purposes:

- `GET /health/live`: process liveness only. It does not check external dependencies.
- `GET /health/ready`: deployment readiness. It returns HTTP 200 only when both the configured SQL database and active LLM provider are healthy. Dependency failures are reduced to `error`; exception text and credentials are never returned.
- `GET /health`: the original provider health endpoint, retained for backwards compatibility.

Container orchestrators and cloud platforms should use `/health/ready`. The Docker image itself uses `/health/live` so a temporary dependency outage does not cause a restart loop.

The external guideline index is intentionally not a readiness dependency in CP-019. The core project currently uses Qdrant Local, and the generated index is not committed. Deployments that need external-evidence search must build or restore the configured `CAREPATH_EVIDENCE_INDEX_PATH` separately before that route is used.

## Environment variables

Application configuration uses the `CAREPATH_` prefix. The main examples are in the repository `.env.example`.

Deployment-specific variables:

| Variable | Purpose | Local Compose default |
| --- | --- | --- |
| `CAREPATH_DATABASE_URL` | SQLite or PostgreSQL SQLAlchemy URL | generated by Compose from the PostgreSQL service |
| `CAREPATH_EVIDENCE_INDEX_PATH` | Qdrant Local persistence directory | `/app/data/guidelines/qdrant` |
| `CAREPATH_ENVIRONMENT` | `development`, `test`, or `production` | `development` |
| `CAREPATH_PRIVACY_MODE` | standard demo or strict local inference boundary | `standard_demo` |
| `CAREPATH_LLM_PROVIDER` | registered provider name | `mock` |
| `CAREPATH_LOG_LEVEL` | application log level | `INFO` |
| `CAREPATH_API_PORT` | host port used only by Compose | `8000` |
| `CAREPATH_POSTGRES_DB` | local Compose database name | `carepath` |
| `CAREPATH_POSTGRES_USER` | local Compose database user | `carepath` |
| `CAREPATH_POSTGRES_PASSWORD` | local Compose database password | required |

Do not commit real database passwords, API keys, tokens, or platform credentials. `deployment/.env.compose` is ignored by the repository-wide `.env.*` rule.

## Cloud deployment blueprint

`render.yaml` defines a Docker-based web service and a managed PostgreSQL database. Both resources explicitly use Render's `free` instance type so a new Blueprint does not silently select a paid default. The backend uses the same `Dockerfile`, migration entrypoint, and `/health/ready` probe as local Compose. Render injects the managed database connection string into `CAREPATH_DATABASE_URL`; no database secret is stored in the repository.

The free configuration is intended only for reviewer/demo use. Render's current free-tier documentation states that free web services can spin down when idle and that free Render Postgres databases expire 30 days after creation. Before confirming a Blueprint deployment, always review the Render dashboard and verify that both `carepath-api` and `carepath-db` are shown as Free / $0. Do not deploy if the dashboard shows a paid instance type.

To create the cloud service, connect this repository as a Render Blueprint and deploy `render.yaml`. No project code change is required. A real cloud deployment requires a Render account/workspace and therefore cannot be created by repository CI alone.

After deployment, verify the public origin with:

```bash
python deployment/verify_backend.py https://YOUR-BACKEND-HOST
```

The verifier requires all of the following:

1. `/health/live` returns `status=ok`;
2. `/health/ready` returns `status=ready`;
3. `/openapi.json` is reachable and includes API metadata.

The public URL should only be recorded in project documentation after this command succeeds.

## CI validation

`.github/workflows/cp019-deployment.yml` builds the production image, starts the full Compose stack with PostgreSQL, waits for health checks, verifies migrations and HTTP endpoints, and tears the stack down on every pull request and on `main`.
