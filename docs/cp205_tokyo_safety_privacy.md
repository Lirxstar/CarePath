# CP-205 — Tokyo safety triage, escalation and privacy boundaries

## Scope

CP-205 inserts a deterministic safety boundary before the CP-204 language layer and CP-203 resource ranking. CarePath Tokyo remains a public-resource navigator; it does not diagnose conditions, recommend medication changes, or treat ordinary resource ranking as an appropriate response to urgent situations.

The boundary defines four dispositions:

1. `routine_navigation` — ordinary bounded Tokyo resource navigation may continue.
2. `insufficient_information` — uncertainty is safety-relevant, so ranking is paused rather than converted into reassurance.
3. `urgent_professional_help` — the request needs professional assessment and ordinary ranking is paused.
4. `emergency_escalation` — ordinary navigation is bypassed and authoritative emergency guidance is returned immediately.

`POST /tokyo/agent/search` runs this boundary before requesting the Tokyo repository or model provider. A blocked request therefore remains safe even when the resource corpus or model is unavailable. Routine requests retain the CP-204 response contract. Blocked requests return `status=safety_boundary` with a deterministic safety decision and source provenance.

`POST /tokyo/safety/triage` exposes the same decision without accepting precise coordinates. It is intended for the Tokyo-first UI in CP-206.

## Deterministic triage

CP-205 reuses `backend.safety.triage.triage_safety` for multilingual high-risk language already covered by CarePath Core, including breathing emergencies, neurological emergencies, serious trauma, severe allergic reactions, immediate self-harm/violence language, diagnosis requests, medication-change requests, and persistent worsening.

Tokyo adds only bounded scenario-specific rules:

- heat context plus inability to walk/stand/move, loss of consciousness, severe confusion, or abnormal behaviour escalates before ranking;
- vague language indicating that the user cannot tell whether a serious situation is an emergency is classified as `insufficient_information` rather than reassured;
- mild heat discomfort without red-flag language remains `routine_navigation`, allowing the frozen cooling-shelter story to continue while preserving source-backed heat-safety guidance in the triage result;
- immediate violence language adds the official 110 reference in addition to medical emergency guidance.

No model output can override the disposition. Prompt-injection text is part of the untrusted query and is classified before the model is reachable.

## Output restrictions

Safety-boundary text is local, frozen EN/JA/ZH wording. It does not:

- diagnose a disease or claim a user has a condition;
- tell a user to start, stop, increase, decrease, or switch medication;
- claim that an unknown resource is open, available, eligible, multilingual, accessible, or reachable;
- convert missing or ambiguous information into reassurance;
- delay urgent help in order to complete resource ranking.

CP-203 remains the factual authority for resource fields. Unknown language support, opening hours, access notes, phone, website, eligibility, and live availability remain unknown unless an authoritative source reports them. CP-204 explanations can select only deterministic reason codes backed by returned resource fields.

## Location and free-text privacy

The Tokyo primary journey is intentionally stateless with respect to precise location and sensitive free text:

- browser coordinates are used for the current search request only;
- the Tokyo routes do not write coordinates or free-text queries to a repository, audit table, or longitudinal profile;
- the API request middleware logs route template, status code, duration, request ID, and bounded error metadata, not request bodies;
- no longitudinal health history is required by `TokyoAgentRequest`, and extra health-history fields are rejected by strict Pydantic validation;
- the safety-only endpoint deliberately does not accept coordinates.

The `TokyoPrivacyBoundary` object makes these defaults machine-readable for blocked safety responses. Any future opt-in durable location feature must be implemented as a separate explicit consent flow rather than weakening this default.

## Automated acceptance

`tests/test_cp205_tokyo_safety.py` covers:

- emergency bypass in English, Japanese, and Chinese;
- safety execution before repository/model access;
- heat emergency escalation and the non-blocking mild cooling-shelter scenario;
- diagnosis and medication-change boundaries;
- uncertainty without unsafe reassurance;
- immediate violence and source-backed 110 guidance;
- authoritative source traceability and retrieval dates;
- prompt injection inside an emergency request;
- rejection of health-history extras;
- no precise location or free-text content in Tokyo API logs;
- unknown resource facts producing `no_match`, not positive claims.

`.github/workflows/cp205-tokyo-safety.yml` runs CP-205 formatting, lint, strict type checks, Tokyo CP-202 through CP-205 tests, the existing Core safety/prompt-injection tests, and a corpus/model-independent emergency API smoke.
