# CarePath v0.8 demo gate

This gate freezes the reviewer-facing main journey after Plan & History adaptation, mobile resilience, accessibility and multilingual safety text are connected.

## Frozen reviewer journey

The automated browser gate executes the following sequence against a real FastAPI backend and an exported Expo Web application served through a same-origin proxy:

1. explicitly switch to a built-in synthetic persona;
2. import the selected synthetic longitudinal package;
3. inspect Today and Health Data trends;
4. ask the prepared health-behaviour question and record the initial 12-minute plan;
5. run the bounded Agent workflow and render the structured verified response;
6. inspect Patient Evidence and expand External Evidence when available;
7. open Plan & History;
8. choose a lighter modified action and submit the reason as structured feedback;
9. refresh the current plan and historical versions;
10. return to Coach, ask again and assert that the persisted feedback reduces the plan to 8 minutes.

`tests/test_cp015_v06_mobile_journey.py` covers the backend import → trends → Agent/tools/evidence → plan → feedback → audit path and separately proves that a persisted modified response changes the next `/coach/message` Planner output from 12 minutes to 8 minutes. `tests/storage/test_v08_plan_adaptation.py` adds the explicit longitudinal adaptation scenarios: repeated high-difficulty rejection reduces the next plan, while stable high completion can increase difficulty.

Synthetic demo profiles are anchored to their latest persisted observation when the runtime builds Agent context. This keeps frozen demo windows reproducible and prevents wall-clock drift from being misclassified as missing data. Profiles without an explicit `synthetic_demo` or `synthetic_data` consent flag continue to use the current time.

## Plan & History acceptance

The v0.8 mobile route exposes:

- current seven-day plan dates, action frequency, difficulty, rationale and persisted status;
- Accept, Reject, Choose lighter option, Complete, Partly done and Not completed outcomes;
- reason capture for rejection and non-completion;
- modified feedback for a user-selected lighter alternative;
- backend plan-history retrieval with stable IDs, plan version, status and supersession link;
- per-version action differences for difficulty, description and status;
- refresh after feedback so persisted action state is visible immediately.

The backend remains the source of truth. Adherence summaries and Planner adaptation consume persisted `PlanFeedback` rather than UI-only state.

## Mobile resilience and accessibility

All four routes are wrapped by a shared resilience layer. Existing page-level loading, empty and controlled API error states remain visible; the wrapper adds explicit offline/API error messaging and an accessible Retry action. Plan & History has its own loading, empty, network, API-error and retry states because it performs both current-plan and history reads.

New interactive controls use a 44 px minimum target. Primary controls expose button/radio roles, selected/disabled state and input labels. `apps/mobile/src/accessibility.test.ts` gates the new touch-target constant, important foreground/background contrast pairs and the presence of multilingual safety content.

Long plan text, citations and small viewports use wrapping, flexible widths and scroll containers. The browser evidence viewport is 390 × 844 to exercise a phone-sized layout.

## i18n baseline

`apps/mobile/src/i18n/` is the canonical mobile resource boundary. English remains the primary reviewer UI language. Navigation/common strings and safety-critical boundaries are available in English, Chinese and Japanese. The language control changes the navigation labels and safety text without changing backend safety policy or user data.

The safety copy in all three languages states that CarePath provides health-behaviour support rather than diagnosis or medication changes, and gives a conservative urgent-help instruction.

## Gate conditions

The v0.8 demo gate passes only when:

- Repository quality is green;
- the real-backend browser journey passes;
- the browser and backend integration tests prove that persisted feedback changes the subsequent Planner output;
- four route screenshots and one recorded browser flow are uploaded;
- Android Expo Go launch smoke passes;
- the adaptation tests for repeated rejection and stable high completion pass;
- no blocker remains open.

Issues discovered during implementation are classified as:

- **blocker** — prevents completion of the frozen main journey or invalidates safety/data isolation;
- **major** — core flow works but a required Plan & History, resilience, accessibility, i18n or evidence function is broken;
- **minor** — cosmetic or low-impact behaviour that does not prevent the reviewer journey.

The merge commit of the PR completing this gate is the v0.8 demo commit. Package/API semantic versions remain independently recorded in the generated manifest rather than being silently changed to match the gate milestone.
